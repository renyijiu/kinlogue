# Kinlogue 项目总览

## 一句话定位

**把你和家人的每次检查，续成各自一条复诊时随手可查的健康记录。**

续页（Kinlogue，读作 KIN-log）是一款 Mac 优先、隐私优先的健康记录应用，以人为单位组织资料。一位用户可以为自己和多位家人导入报告图片/PDF，在本机完成 OCR 和人工确认，建立可检索时间线，并随时回到原件核对。产品负责整理、检索和呈现来源明确的记录，不替代医生，也不提供诊断结论。

当前形态是本机明文资料库，加上用户主动开启的临时局域网投递、用户选择目录的加密恢复点和默认关闭的 AI 对话（实验）。App 自己不访问互联网或云服务；只有用户开启 AI 对话并在每段对话发送前确认后，用户本机已登录的 Codex 才会把一位成员的已确认报告转录发送给它所登录的服务。局域网接收使用普通 HTTP，只适用于可信任私人网络。备份只写文件夹，不调用网盘 API，也不能观察远端上传状态。候选版本、自动化状态和未完成人工门禁只在 [`acceptance/current-release.md`](acceptance/current-release.md) 维护。

当前最低支持 macOS 26，主要面向个人自用；macOS 26 以下版本不再支持。系统下限不等于兼容性已验收，当前证据仍以候选账本为准。

## 核心用户与任务

核心用户是使用一台 Mac 为自己和家人整理健康资料的人。主要任务不是“自动理解病历”，而是：

1. 把散落的报告原件收进一个本机资料库；
2. 核对 OCR 候选并明确归属到家庭成员和日期；
3. 在复诊前沿时间线找到历史记录，并能回到原件确认来源；
4. 必要时把已确认原件导出给医生查看或打印。
5. 把完整资料库保存为可在另一台 Mac 恢复的加密恢复点。

手机上传、DICOM Viewer、原始文件导出和 AI 对话都服务于这条主任务，不各自扩张成独立平台。AI 对话只帮助理解已确认的报告，不替代核对原件，也不是诊断渠道。

## 当前用户流程

### 报告导入与确认

1. 用户从 Finder 选择图片或 PDF，或从临时 LAN inbox 选择已接收原件。
2. App 验证类型和资源上限，将原件复制到 Vault，再用 PDFKit/Vision 在本机生成 OCR blocks。
3. 候选字段和来源进入待确认草稿；未经确认的内容不进入正常时间线、搜索或比较。
4. 用户核对原件、修正文字、选择成员和日期后，App 原子提交已确认记录。

复核页和已确认记录的编辑页会在检查结果下列出几种已知的识别误读，例如把“↑”读成“个”，由用户逐条采纳或忽略，不会自动替换。识别规则更新后，打开由旧规则整理的已确认报告时，详情页会提示哪些字段可以按新规则重新整理；用户逐项对照后决定，默认全部保留，原件不会重新识别。

### 搜索

搜索只查已确认记录，结果按时间线顺序排列，每张卡片显示报告日期，卡片上出现的搜索词加粗标出。搜索词出现在检查结果的表格行里时，卡片逐格列出这些行的原文，例如项目、结果和参考值；按成员筛选后即可看到这个人某一项目的历次记录。搜索词落在叙述型报告（例如超声、CT）的检查结果或结论里时，卡片列出含搜索词的句子，最多 3 句，并标明出自哪个字段，同一部位的历次描述按日期排开。搜索词落在卡片没有显示的其他字段里时，卡片显示命中处的一段上下文。这是对已确认原文的呈现：不解析数值、不画趋势、不判断正常与否。取舍见 [`decisions.md`](decisions.md)。

### 手机局域网投递

1. 用户在 Mac 明确开启临时会话，并确认当前网络可信。
2. 手机浏览器通过一次性配对码逐文件上传，只能查看当前会话状态。
3. Mac 负责权威去重、预处理和待确认队列；报告分组、页序、成员和日期都由 Mac 用户决定。
4. 停止接收、锁屏/睡眠、网络变化、最后窗口关闭或退出都会撤销会话；不会自动恢复。

### DICOM 文件夹导入

DICOM 是受限的辅助能力，不是通用 PACS、影像工作站或诊断工具。用户从独立入口选择文件夹，App 以无内容聚合进度导入一个检查，确认成员和日期后才显示检查级时间线入口。当前 Viewer 只覆盖明确列出的二维灰度 MR 子集；详细支持范围和隔离边界见 [`dicom.md`](dicom.md)。

### 全部原始文件导出

用户可从“设置 → 数据管理”生成一个明文 ZIP，内容仅为已确认报告和 DICOM 的原始附件。它不包含 OCR、转录、备注、数据库、草稿或待确认项，不能恢复资料库，也不会随 App 内资料库删除而被清除。

### 加密目录备份与恢复

用户可从“设置 → 数据备份”选择一个父目录，保存恢复码，手动创建恢复点或开启自动备份，并设置保留 2–30 份。App 在选定目录中创建专用 repository；若该目录属于阿里云盘、百度网盘或其他客户端，上传和远端保留仍由对应客户端负责。

恢复使用一个 `.kinloguebackup` 和恢复码，在私有 staging 完整验证后由用户明确确认替换整个 Vault 与 durable LAN inbox；不做记录级合并。资料库无法正常打开时仍保留恢复入口。详细契约见 [`backup-and-restore.md`](backup-and-restore.md)。

### AI 对话（实验）

1. 用户在“设置 → AI 对话（实验）”开启功能；续页检查本机 Codex 的位置、版本、登录状态，并对本机模拟服务做一次不耗额度的请求检查。模型从本机 Codex 列出的模型中选择（设置页的下拉菜单，或对话面板顶部接收方一行的菜单），不选时用 Codex 的默认模型。
2. 选中一位成员后，工具栏“对话”把详情栏换成这位成员的对话。每段对话第一次发送前，确认页列出接收方和全部发送内容；内容、Codex 或模型变化后要重新确认。
3. 用户提问；续页把在本机由这位成员已确认报告整理成的分层上下文（最多 300 份报告的目录、结论与标记项、按检验项目汇总的结果行、预算内最新报告的全文，约 100 KB）、此前问答和问题经 stdin 交给 Codex。回答标明由模型生成，引用 `[R#]` 可以点开对应报告。
4. 完成的每一轮都保存在资料库里，面板的“历史对话”可以重新打开或删除；重新打开后第一次发送仍要确认。对话随恢复点备份、随成员删除，关闭功能不会删除它们。执行边界见 [`privacy-and-security.md`](privacy-and-security.md)，验收状态见 [成员对话验收矩阵](acceptance/member-chat-matrix.md)。

## 产品验收契约

首发前用以下结果判断产品是否解决核心问题：

- 用户能把一份报告从原件导入推进到明确成员和日期的已确认记录；
- 每条确认内容都能回到对应原件或来源位置核对；
- 未确认 OCR、DICOM 自由文本和像素不会进入报告搜索、比较或新的医学结论；
- 重启、失败、取消和并发写入后，只能看到完整旧状态或完整新状态；
- 用户能在复诊场景中找到历史记录，并显式导出需要分享的已确认原件；
- 删除、导出和局域网接收的范围在操作前对用户可见。
- AI 对话只发送确认页列出的内容；回答与已确认记录分开显示，标明由模型生成，引用能回到对应报告。
- 备份成功只表示本地恢复点完整可读；错误恢复码、损坏文件或恢复取消不会改变当前资料库。

这些产品假设仍需真实用户或人工矩阵验证，不能由自动化测试替代：

- 真实私有样本上的 OCR 候选是否足够减少整理成本；
- 多家庭成员的时间线是否符合复诊前查找习惯；
- 受限 DICOM Viewer 是否确实帮助查看原件，而不是扩大产品范围；
- 导出的目录结构是否方便医生查看或打印；
- 键盘、VoiceOver、真实手机和不同 macOS 版本上的流程是否可用。
- AI 对话的回答是否守住非诊断边界、引用是否有效，以及它是否真的帮助理解报告。

## 当前明确不做

- 账号、多人协作、内置云同步、网盘 API、iCloud、CloudKit、HealthKit、续页自己的互联网服务或内置模型服务、遥测、广告和第三方崩溃上报；
- AI 对话的工具调用、按问题检索、保存对话、跨成员对比，以及 Claude Code 等其他 CLI；
- 活动 Vault 的应用层加密、Keychain、后台守护进程和自动云端迁移；
- 自动诊断、趋势分析、治疗建议或没有来源依据的新结论；
- 手机浏览 Mac 上的成员、历史记录、OCR、时间线或原件；
- LAN 后台常驻、自动恢复、传输加密或公共网络安全承诺；
- DICOM 诊断、测量、MPR/MIP、三维重建、PACS/DICOMweb 或未列入支持矩阵的格式。

## 必须保持的产品不变量

- **来源优先**：OCR 是候选，修正仍保留原始转录和来源引用。
- **确认门**：只有已确认报告进入时间线、搜索和比较；只有已确认 DICOM 显示检查级入口。
- **完整提交**：原件先写入并同步，引用它的记录在同一个数据库事务里发布；中断后只会看到旧状态或完整的新状态。
- **显式生命周期**：接收、删除和导出都由用户明确发起；迟到任务不能在撤销后重新发布资料。
- **导出非备份**：ZIP 是外部明文副本，不是可恢复资料库。
- **备份非云同步**：加密恢复点是完整 checkpoint；没有 provider API 时只证明本地目录，不证明云端上传或远端份数。
- **隐私诚实**：明文、普通 HTTP、AI 对话的外发与不可撤回、非诊断和未执行门禁始终保持可见。
