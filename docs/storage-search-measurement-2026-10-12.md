# SQLite 搜索复测（2026-10-12）

本页记录搜索改为“预筛键 + 按摘要缓存”之后的规模测量，接续 [首批存储重构实测](storage-refactor-measurement-2026-10-11.md#sqlite-按需查询) 中未通过的搜索门槛。实现说明见 [SQLite 存储专题](sqlite-storage.md#app-查询与提交观察)，门槛定义见 [重构计划](plans/2026-10-10-2322-refactor-sqlite-architecture-plan.md)。

## 环境与口径

Mac13,1 / M1 Max / 64 GB / 内置 APFS；macOS 27.0.1（26A434）、Xcode 27、Swift 6.4。探针是 `-c release -Xswiftc -warnings-as-errors` 构建的 [独立 fixture](../Sources/KinlogueStorageProcessFixture/StorageScaleProbe.swift)，没有加入主测试清单。

资料库由 `logical-generate --reports 9990` 在本次重新生成：9,990 份报告、9,791 条已确认记录、199 份草稿，每份 60 个 OCR block、64 KiB 原件，数据库 375,304,192 bytes，全部是运行时合成内容。生成耗时 361 s。

每个查询先各运行一次不计时的参考路径和被测路径，再串行采样 20 次。参考路径逐行解码并使用 Core 的 `RecordQuery.matchesSearchTerm`，不使用预筛键和缓存；被测路径的完整有序 ID 与损坏 ID 必须与它相同，否则探针失败。p50 取排序第 10 项，经验 p95 取第 19 项。“首页”是 `reportPage` 返回前 100 条摘要，“完整结果”是全部命中的有序 ID。测量期间没有运行其他构建或测试；不是冷缓存测量，也没有记录全机负载。

## 结果

基线由合并 main 之后、搜索改动之前的同一份源码构建，在同一个资料库上测得，与此前记录的数字一致。

同一二进制紧接着的另一轮里，无匹配查询的首页 p95 / max 为 44.207 / 46.903 ms、完整结果为 41.658 / 42.815 ms，其余各项与上表相差不到 2 ms。两轮中所有固定词的 p50 都低于 50 ms、p95 都低于 100 ms。

完整结果的 SQL 读取中位数约 16.5 ms，其中读取报告目录约 7.5 ms；最大候选批 737,170 bytes，最多八个 lane。进程峰值 footprint 79,774,488 bytes，高于改动前的 23,118,568 bytes，增量来自解码缓存和 32 MiB 的连接页缓存。

新进程里的第一次搜索还要解码全部搜索行并生成预筛键：两轮分别为 51.3 ms 和 49.1 ms。之后的查询 9,791 行全部命中缓存。

页缓存调整后在同一资料库上重跑了两项既有探针：新进程打开存储并读取首批 100 条为 192.116 ms，Ready 前原件读取 0 bytes；20 次短操作里 64 KiB 导入 p95 37.835 ms、保存复核 p95 9.164 ms、确认 p95 10.407 ms、编辑 p95 9.622 ms、32 KiB LAN 发布 p95 34.334 ms，峰值 footprint 40,059,528 bytes。

## 边界

- 这是 macOS 27 上 Platform repository 到 DTO 的计时。macOS 26、安装后的 App、可见更新和 OS 冷缓存没有测量。
- 合成文本以中文和 ASCII 为主。不含字母或数字的搜索词没有预筛键，每个字段都要经过 Foundation 谓词，耗时接近改动前；这种词没有测量。
- 缓存预算是 64 MiB。超出预算的行每次查询重新解码，结果仍然正确，但没有测过这种规模。
- 首页不再提前结束扫描，命中很多的查询首页从约 12 ms 升到约 35 ms，换来所有查询的耗时相近。
- 原始样本保留在本机探针产物中，不含真实资料，也不进入 Git。
