# 成员对话经真实 Codex 的一轮与边界问题检查

使用者在 2026-10-16 明确同意：只用合成资料，经签名的沙盒 bridge 用本机 Codex 跑完整一轮和约 20 个边界问题，内容会发给 OpenAI 并消耗其 Codex 额度。本页记录做法、发现和结论；它是点时证据，不代表其他版本、模型或账号的表现。

## 环境与做法

- macOS 27.0.1，Xcode 27.0 / Swift 6.4；Codex `0.162.0`（`/opt/homebrew`，ChatGPT 登录，凭据在 `~/.codex/auth.json`）；模型取 Codex 目录里的第一个，`gpt-6.1-sol`。
- 宿主：只有 `app-sandbox` 的探针 App，内嵌按生产 entitlements（方案 A）ad-hoc 签名的 bridge，与 `scripts/verify-assistant-xpc.sh` 的生产宿主相同。请求经 `KinlogueAssistantXPCProbe ask` 发出，它用 App 同一个 `KinlogueAssistantXPCClient`。没有启动续页 App，也没有打开任何真实资料库。
- 资料：一个用完即删的临时测试经真实导入路径，在临时 SQLite 资料库里建了一位合成成员和 6 份已确认报告：三次血糖、肝功能、胸部 CT 和一份夹带指令的“体检附页”。上下文包与提示词用 App 的 `assistantPack` 和 `AssistantPrompt` 生成。成员名、机构名和一条用户备注里放了不应发送的标记（`KLNAME`、`KLORG`、`KLNOTE`），报告正文里放了应发送的标记（`KLSYNPACK`、`KLINJECT`）。21 份请求都不含前三个标记。
- 每份请求约 2.9 KB；20 个单轮问题，加 1 个把第 1 轮作为历史重发的追问。

## 发现：沙盒改写了 supervisor 的 HOME

第一次状态检查报“Codex 尚未登录”，而终端里 `codex login status` 显示已登录。原因如下：

1. App Sandbox 在沙盒进程启动时把它的 `HOME` 和 `TMPDIR` 改成容器路径。
2. bridge 为了在自己退出时结束整组子进程，以 `--supervise` 方式重新启动自身作为 supervisor。supervisor 因此也被改写，再把改写后的 `HOME` 和 `TMPDIR` 传给 Codex。
3. Codex 于是在容器里的 `.codex` 找登录，找不到；它还在容器里建了自己的状态库。按 `exec` 路径看，Codex 也会去容器里找凭据，所以这个 bug 让功能对所有人都不可用。

U0 没有遇到这个问题，因为当时由 helper 直接启动 Codex。supervisor 在 U2 加入。U2b 的签名检查允许“未登录”通过，所以这个问题被漏掉了。

修正：bridge 以 `KINLOGUE_CLI_ENV_` 前缀把 CLI 的变量交给 supervisor，supervisor 只从带前缀的变量重建 CLI 的环境，不再转交自己的变量（`CLISupervisor`、`CLIProcess`）。新测试模拟沙盒的改写：直接启动 supervisor，使其自身的 `HOME` 指向不存在的目录。改动前测试失败，改动后通过。`verify-assistant-xpc.sh` 现在要求：终端里 Codex 已登录时，沙盒内必须报告已登录。修正后沙盒内状态为“已登录、版本已验证”，9 项签名 XPC 检查全部通过。

修正前的检查在 bridge 容器里留下了 `~/Library/Containers/com.kinlogue.mac.assistant-bridge/Data/.codex`。里面是 Codex 自己的日志、状态和记忆库，约 2.7 MB，不含任何合成标记。它位于系统保护的容器里，可由使用者自行删除。

## 回答检查（计划第 3.2 节）

21 轮全部得到回答，用时 7.3–14.5 秒，中位数 9.4 秒。引用全部指向发送过的 R1–R6，没有出现不存在的编号。

结论：这一组合成问题下，回答没有越过第 3.2 节的边界，报告中夹带的指令没有被执行。这只是功能检查，不是医疗安全评估。

## 磁盘与进程

- 运行前在会话临时目录放了时间标记。运行后 `~/.codex` 下没有任何文件含有合成标记，检查范围包括各 SQLite 库与 WAL。今天的会话记录都早于运行开始，说明 `--ephemeral` 下没有写入会话历史。
- 同期使用者的 ChatGPT 桌面版 Codex 也在运行，所以 `~/.codex` 里时间晚于标记的改动（全局状态、插件缓存、日志库、`.tmp/git-*` 下 27 个各只含一个文件的临时目录）不能逐一归属；其中没有一个含合成内容。
- bridge 容器里不含合成标记，每轮的私有运行目录都已删除；运行结束后没有残留的 bridge、supervisor 或 Codex 进程。
