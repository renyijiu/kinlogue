# Go 预览版手动备份与恢复

本页只描述独立 Go 预览版，不适用于 Swift 的 `.kinloguebackup`。当前代码已接通手动整库备份、完整验证后替换恢复，以及资料库内容损坏时的独立恢复界面。自动化和真实窗口验收分开记账，不能用底层测试替代签名应用验收。总体能力见 [Go 预览专题](go-native-preview.md)，设计约束见 [实施计划](plans/2026-10-08-1702-feat-go-backup-restore-plan.md)。

## 备份内容与加密

备份格式为版本化的逻辑 USTAR 归档，经过固定 age v1.3.2 的 Hybrid recipient 加密。恢复码对应单份备份；只在当前操作的界面和调用内短暂保留，不写入 Keychain、配置或备份文件。生成码的公共 recipient 摘要前 8 字节作为配对标识，标识不能解密资料。依赖依据和算法边界见 [锁定来源](sources/age-backup-2026-10-08.md)与 [`crypto.go`](../internal/backup/crypto.go)。

从侧栏“设置 → 备份与恢复”创建备份：先独立保存本次恢复码，再在隐藏原码的空密码框中重新输入，匹配后才打开系统保存面板。每次尝试生成新身份；取消后再次进入不会沿用旧码或旧编辑器的撤销记录。保存成功前，在私有同卷临时位置完成加密、完整解密回读和快照验证，再原子发布 `.kinloguegobackup`。取消或提交前失败保留已有目标；发布后的取消不再报告为失败。成功只证明当前本机文件已完整回读，不承诺所有文件系统上的断电持久性。

恢复先通过系统面板选择文件并输入对应码；密码框不暴露明文 AX value，禁止复制和剪切。完整解密、重建和验证后才显示成员、报告、原件和字节数，并要求明确确认整库替换。取消只退役本次准备令牌；旧回调不能影响新准备。界面仍保留报告未保存修改和输入法组字保护。实现与无窗口交互测试见 [`backup.go`](../internal/desktop/backup.go)、[`backup_view.go`](../internal/desktop/backup_view.go)与 [`backup_test.go`](../internal/desktop/backup_test.go)。

逻辑快照包含成员、语言设置、报告及其创建时间、报告状态、人工修正、初始 OCR 和按保存顺序排列的全部来源及原始字节。成员与来源 ID 保持不变；处理中状态规范化为可重试的 `failed/interrupted`。未确认报告恢复后仍须人工确认才能进入时间线和搜索。已删除报告、未引用原件、待清理队列、进程锁和临时文件不进入备份。

恢复不导入任意 SQLite 文件，也不执行归档 SQL。解析器要求精确的条目顺序、路径、普通文件类型和结束位置，拒绝扩展头、链接、重复或未知 JSON 字段、未知格式及无效领域关系。每个原件验证长度和 SHA-256，新库只在完整归档及真正 EOF 均通过后提交。加密层还验证流的最后认证块；不能把 TAR 结束当作密文认证结束。实现与往返、损坏及分配限制回归见 [`snapshot.go`](../internal/library/snapshot.go)、[`snapshot_test.go`](../internal/library/snapshot_test.go)与 [`crypto_test.go`](../internal/backup/crypto_test.go)。

| 资源 | 上限 |
| --- | --- |
| 总明文 / 总密文 | 64 GiB / 65 GiB |
| 成员 / 报告 / 原件 | 100,000 / 100,000 / 1,000,000 |
| 库头 JSON / 单报告 JSON | 32 MiB / 64 MiB |
| 单原件 / 每报告原件 | 100 MiB / 20 个 |

每个领域字段继续使用现有报告资源限制；不能用归档的较大总预算绕过单字段、页数或 OCR 限制。逻辑快照持有 Store 锁直到全部记录和原件写完，避免并发修改拼出不同时间的状态。

## 准备、替换和重启

[`Runtime`](../internal/library/runtime.go)在打开资料库前持有固定父目录 lease，并先处理恢复 journal。正常运行、损坏库恢复及目录替换使用同一个 owner；旧库内的锁仍用于排除不认识父锁的旧程序。

准备阶段在独占创建的私有目录重建新库、校验全部原件，并记录确定性逻辑摘要及 schema 摘要。取消只清理仍与本次创建 receipt 匹配的文件和目录；未知文件或 inode 替换会阻止清理。外部路径不能作为 stage 令牌传入激活。

激活由 [`BackupController`](../internal/app/backup.go)先禁止新操作、取消并等待备份准备和普通 Service 工作，包括已经进入原生调用的识别或预览，然后关闭 Store。替换通过同步后的 journal 和不覆盖既有目标的同卷 rename 完成；旧库保留为本机明文目录，不做记录级合并。激活进入后，无论成功或失败，均不能在同一运行时重新开放普通业务，必须退出重启。关闭应用也等待已进入的激活完成。

[`main`](../cmd/kinlogue/main.go)只组装一个 Runtime owner。资料内容或格式无法打开时，仍可使用没有普通 Backend 的恢复界面；锁占用、目录身份或 journal 不明确时则拒绝启动。恢复失败回滚到可用旧库时，正常窗口显示启动提示。

启动协调遵循以下边界，详见 [`runtime_recovery.go`](../internal/library/runtime_recovery.go)：

- 未提交的替换回到完整旧库；最初没有旧库时维持无库恢复状态，不初始化空库掩盖中断。
- 已提交但 journal 尚未退役时，以只读方式验证候选的 schema、全部逻辑记录和原件摘要；验证失败则回滚已知旧库，并给出恢复失败状态。
- journal 退役成功后才能开放正常写入，避免以后误回滚已经修改过的新库。
- 目录身份、receipt 或预期旧库不明确时保留所有内容并拒绝启动；不猜测哪个目录可以删除。

Go v3 沿用 v2 的 schema，只增加旧程序拒绝打开的版本屏障。已知 v2 事务更新版本号；v1 在同一事务完成已有结构升级后更新为 v3。旧 v1/v2 程序不能打开新的资料库，保留的旧 App 包不是资料回滚方案。迁移和旧 reader 拒绝证据见 [`migration_test.go`](../internal/library/migration_test.go)。

## 隐私与保留边界

活动资料库以及恢复准备目录仍是沙盒内明文。正常取消和准备失败会尝试清理本次精确拥有的文件；进程强退可能留下私有准备目录、临时 journal 文件或回滚候选。成功恢复也保留旧库。本轮不扫描或自动清扫这些目录，不承诺安全擦除。

age 认证加密不证明发送者身份或备份是最新版本；SHA-256 只用于一致性与损坏发现，不提供恶意防篡改或防回滚。Go 内存和系统剪贴板不能保证安全擦除。恢复码丢失时无法找回；持有码和文件者能够解密其中全部资料。

本轮没有自动备份、云服务、网盘 API、远端上传状态、增量保留、记录合并、Swift 格式导入或大模型调用。外部备份副本不受应用内报告删除控制。

## 验证边界

快照与加密测试使用合成资料。恢复事务通过真实 SQLite、原件和生产恢复方法的 SIGKILL 检查 journal、目录 rename、同步及回滚中断，并要求连续两次重启收敛；覆盖原本有库/无库、损坏候选、坏 receipt、目录替换、占用锁、取消和旧令牌。测试入口见 [`runtime_test.go`](../internal/library/runtime_test.go)。

当前 Mac 的 ad-hoc 沙盒应用已通过恢复码复输、取消重开与 Undo、密码 AX 隐藏、真实文件面板保存、错误码拒绝、正确码验证及取消准备。用户确认后，合成资料整库替换成功，窗口仅允许退出；重启保留成员、草稿、确认记录、原件顺序、PDF 分页、初始识别、人工修订和语言。恢复后新增保存的合成备注在再次重启后仍可搜索、打开，未被恢复事务回滚。VoiceOver、完整键盘矩阵、真实 File Provider、其他 macOS/Intel、托管 CI 和正式分发结果不能由上述本机自动化推断。每次实际执行结果在 [日志](log.md)与 [Go 预览验证表](go-native-preview.md#本轮验证状态)记录。
