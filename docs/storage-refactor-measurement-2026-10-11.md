# 首批存储重构实测（2026-10-11）

本页记录 `codex/sqlite-refactor` 基于 `09f57b1` 的未提交工作树结果，不是 clean-source 发布候选，也不是 SQLite 生产切换后的性能。改动与剩余工作见 [SQLite 内核](sqlite-storage.md)、[实施日志](log.md)；修复前输入见 [测量来源](sources/2026-10-11-storage-plan-revision-evidence.md)。

## 环境与口径

Mac13,1 / M1 Max / 64 GB / 内置 APFS；macOS 27.0.1（26A434）、Xcode 27、Swift 6.4、Release。全部数据为运行时生成的合成内容；无真实病历。复用 [独立探针](../scripts/run-storage-scale-probe.sh)，没有加入主测试清单。操作 7 次采样取中位数；启动为三个新进程、热缓存；备份及严格恢复各完整执行一次，不能标成 p95。主流程串行执行规模采样、构建和主测试。初期一个独立 Swift 语义探针用时 0.232 s，可能与小库采样短暂重叠；此后停止其他编译。不是整台机器完全空闲或冷缓存的测量。

报告近上限档为 9,990 份报告、9,791 条确认记录、19,980 个 Vault 对象、约 55 MiB manifest；每份原件 64 KiB。保存、确认和导入采样会在该合成库上留下少量持久变更，因此后续备份条目数包含这些变更。

## 验证边界

以上规模采样在审查收尾的 OCR 并发修复前完成；后者抽取共用提交实现、为 processing 转换增加同一 mutation lease 内的合并，并补 App 重试状态，没有更改本页测量的备份格式、读取算法或去重算法。本页保留采样时点结果，不冒充后续工作树的重复性能验收。

当前 App 仍使用 JSON。U11–U13 的前置修复不替代 U4/U5 领域读写、U8 按需查询、U6 逻辑备份或 U7 切换；当前容量格式仍承载 JSON 快照。未测冷缓存、真实 UI、macOS 26、外置盘/NAS/网盘传播、真实 OCR 或 DICOM 解码；严格恢复耗时包含真实 staging 校验与 activation，但不是安装后人工恢复验收。


## SQLite 逻辑捕获

以下是后续 U6 的独立 Release 探针，不是上文 JSON 数据复测，也不是生产切换结果。通过真实 SQL repository 创建同形状的 9,990 份报告（9,791 confirmed、199 draft、每份 60 个 OCR block），9,990 个 64 KiB 原件，数据库 375,336,960 bytes；生成耗时 348.602 s，不计入操作。

最初在 admission 内做全部逻辑验证，5 秒时只处理约 3,081 份 OCR，按预算超时。改为在 admission 内复制应用自己的数据库，随后从冻结副本校验完整逻辑图；对外格式仍是 logical-v1。内部副本最初造成约 98.75 MiB 增量，超过 96 MiB 预算。5 ms footprint 采样与分阶段观测将峰值定位到 native backup，缩小 cache_size 本身无效。本机 engine 回读 cache_spill 为 20,000 pages；按 [官方阈值规则与本机证据](sources/2026-10-11-sqlite-capture-cache.md) 同时限制临时副本的 cache 和 spill，并验证实际回读，不改变源库持久性。

### 超过 20,000 条容器条目的独立容量证明

`logical-capacity` 通过真实 `SQLiteReportRepository.stage` 创建 20,000 个唯一 1,024-byte 草稿原件，再通过真实 LAN sink 写入 1 个不同原件并保存有效 derived document；生成耗时 **374.668 s**。只有该命令的报告参数上限放行至 20,000，现有 JSON / logical-generate 仍保持 10,000 参数上限。未处理草稿在逻辑备份中按既有契约归一化为 failed/cancelled；恢复后全部 20,000 drafts、1 LAN item、receipt 与 derived 关系通过真实读取核对。

真实 capture callback 记录 **20,001 个原件**；逻辑流至少占一个额外容器条目，所以外部条目数推导下界为 **20,002**，已超过旧 20,000 上限。这里没有读取并声称实际 manifest entryCount，明确保留为推导下界，也没有把旧 JSON 的 reports-20000 对象标签当成 SQL 条目数量。

本档实际原件共 **20,481,024 bytes**；从严格恢复总明文扣除原件，逻辑流为 **8,341,675 bytes**，小于代码中的 1 GiB segment。按当前固定内部路径和 canonical 编码推导，单 segment 的 manifest 为 **2,480,366 bytes**，payload frame 共 **20,033**（每个小原件一帧，加逻辑流逐 256 KiB 向上取整）。这与 [格式约束](../Sources/KinlogueCore/Backup/BackupCheckpoint.swift) 的 30,002 entries、32 MiB manifest、2²⁴ frames 和名义 4 TiB 明文预算分别核对；这些推导不扩大资料库/LAN 限制，也不以所有维度理论最大值相乘来替代真实闭环。
